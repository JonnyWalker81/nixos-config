## Objective

Set up the infrastructure for the entire OrgLife project: add `+roam` and `+journal` flags to init.el (pulling in packages early for future phases), register the new `config-org-gtd.el` module in config.el's loader chain, create the skeleton `config-org-gtd.el` file with `org-directory` and `org-agenda-files` configured inside `after! org`, and scaffold the GTD directory structure with boilerplate org files.

## Context

- init.el org section (line 190-197) currently has: `+pretty +attach +babel +capture +export +present`
- config.el loads modules sequentially (line 205-206 loads config-org); new config-org-gtd must load AFTER config-org
- dotfiles.nix deploys `users/doom.d/` recursively to `~/.doom.d/` — new files automatically get symlinked
- No new packages.el entries needed for Phase 1 (org-super-agenda already declared, org-roam-ui deferred to Phase 5)
- CRITICAL: Doom overrides org settings — all config must go inside `(after! org ...)` blocks

### Discretion Decision: org-directory

Setting `org-directory` to `~/org/` (NOT `~/org/gtd/`). Rationale:
- Phase 5 uses `~/org/roam/`, Phase 6 uses `~/org/journal/` and `~/org/denote/`
- `~/org/` as the parent directory is the natural umbrella for all org subsystems
- `org-agenda-files` will point specifically to `("~/org/gtd/")` to scope agenda to GTD files only
- This avoids future config churn when adding roam/journal directories to agenda

## Requirements Covered

- **GTD-04** (partial): org-directory set, GTD file structure created (inbox.org, projects.org, someday.org, reference.org, archive/)

<task id="01-01-3">
<title>Create config-org-gtd.el skeleton with org-directory and agenda-files</title>
<detail>
Create `users/doom.d/config-org-gtd.el` as a new file with the foundational settings.

```elisp
;;; config-org-gtd.el --- GTD workflow configuration -*- lexical-binding: t; -*-

;; ============================================================================
;; GTD FOUNDATION
;; ============================================================================
;; Core GTD primitives: org-directory, file structure, TODO states, context tags,
;; refile, priorities, and effort properties.
;;
;; All settings use (after! org) to survive Doom Emacs overrides.

(after! org
  ;; --------------------------------------------------------------------------
  ;; Directory & File Structure
  ;; --------------------------------------------------------------------------
  ;; ~/org/ is the umbrella for all org subsystems:
  ;;   ~/org/gtd/     — GTD agenda files (inbox, projects, someday, reference)
  ;;   ~/org/roam/    — org-roam knowledge base (Phase 5)
  ;;   ~/org/journal/ — org-journal daily entries (Phase 6)
  ;;   ~/org/denote/  — denote structured notes (Phase 6)

  (setq org-directory "~/org/")

  ;; Agenda scoped to GTD files only — prevents roam/journal noise in agenda
  (setq org-agenda-files '("~/org/gtd/"))

  ) ;; end after! org

(provide 'config-org-gtd)
;;; config-org-gtd.el ends here
```

This is intentionally minimal — Plan 01-02 will add TODO states, tags, priorities, and effort inside this same `after! org` block.
</detail>
</task>

<task id="01-01-4">
<title>Create GTD directory structure and boilerplate org files</title>
<detail>
Create the following directory structure and files. These files will live on the actual system at `~/org/gtd/` — they are NOT part of the nixos-config repo. They must be created on the target machine after deployment.

Add an elisp block to config-org-gtd.el that ensures the directory structure exists at Emacs startup:

```elisp
;; --------------------------------------------------------------------------
;; Auto-create GTD directory structure
;; --------------------------------------------------------------------------
;; Ensure directories exist on first run (idempotent)

(dolist (dir '("~/org/" "~/org/gtd/" "~/org/gtd/archive/"))
  (unless (file-directory-p (expand-file-name dir))
    (make-directory (expand-file-name dir) t)))

;; Create GTD files with boilerplate if they don't exist
(dolist (file-spec '(("~/org/gtd/inbox.org"     "Inbox"     "Capture landing zone — process to zero regularly")
                     ("~/org/gtd/projects.org"   "Projects"  "Active projects with sub-tasks")
                     ("~/org/gtd/someday.org"    "Someday"   "Maybe/someday items — review weekly")
                     ("~/org/gtd/reference.org"  "Reference" "Non-actionable reference material")))
  (let ((filepath (expand-file-name (nth 0 file-spec)))
        (title (nth 1 file-spec))
        (desc (nth 2 file-spec)))
    (unless (file-exists-p filepath)
      (with-temp-file filepath
        (insert (format "#+title: %s\n#+filetags:\n\n# %s\n" title desc))))))
```

Place this block BEFORE the `(after! org ...)` block in config-org-gtd.el (it runs at load time, doesn't need org to be loaded).

This ensures the GTD file structure is self-bootstrapping — no manual directory creation needed.
</detail>
</task>
