## Objective

Implement the core GTD configuration inside `config-org-gtd.el`: 6 TODO states with fast-selection keys and LOGBOOK timestamp logging (WAITING prompts for a note), 6 GTD context tags with fast-tag interface, priority A/B/C with color-coded faces, and t-shirt size effort properties. All settings go inside the existing `(after! org)` block to survive Doom's silent overrides.

## Context

- Doom sets its own `org-todo-keywords` (TODO/PROJ/STRT/WAIT/HOLD/IDEA/DONE/KILL) — our `setq` inside `after! org` will override these
- Doom also sets `org-todo-keyword-faces` — must override completely
- The `(after! org)` block in config-org-gtd.el from Plan 01-01 needs to be expanded with all the new settings
- CRITICAL: `org-todo-keywords` must use the `(sequence ...)` form with fast-selection keys in parentheses

### Discretion Decisions

**Priority face colors** (matching doom-tokyo-night palette):
- Priority A: `#ff6c6b` (red) — bold, urgent
- Priority B: `#ECBE7B` (yellow/amber) — moderate importance
- Priority C: `#98be65` (green) — low priority, nice-to-have

**Additional tag categories**: None beyond the 6 GTD contexts. Energy/complexity is handled by the effort t-shirt size property — adding energy tags would create redundancy. Keep the tag namespace clean.

**LOGBOOK formatting**: Standard org format — `org-log-into-drawer` set to `"LOGBOOK"`. State changes produce `- State "STATE" from "PREVSTATE" [timestamp]` entries automatically.

## Tasks

<task id="01-02-1">
<title>Configure TODO states with fast-selection keys</title>
<detail>
Add to the `(after! org)` block in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; TODO States
  ;; --------------------------------------------------------------------------
  ;; 4 active states | 2 closed states
  ;; Fast-selection keys in parentheses: t=TODO, n=NEXT, w=WAITING, s=SOMEDAY, d=DONE, c=CANCELLED
  ;; The pipe (|) separates active from closed states.
  ;; Transitions are unrestricted — any state can move to any other.

  (setq org-todo-keywords
        '((sequence
           "TODO(t)" "NEXT(n)" "WAITING(w@/!)" "SOMEDAY(s)"
           "|"
           "DONE(d!)" "CANCELLED(c!)")))
```

Key syntax details:
- `(t)` = fast-selection key only, no logging beyond what org-log-done provides
- `(w@/!)` = on entering WAITING, prompt for a note (@); on leaving WAITING, log timestamp (!)
- `(d!)` = on entering DONE, log timestamp
- `(c!)` = on entering CANCELLED, log timestamp

Note: The `@` on WAITING means entering WAITING always prompts for a note (who/what you're waiting on). The `!` after the `/` means leaving WAITING logs a timestamp. All other states only log timestamps (handled by the `!` or by `org-log-done`).
</detail>
</task>

<task id="01-02-2">
<title>Configure state change logging into LOGBOOK drawer</title>
<detail>
Add to the `(after! org)` block in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; State Change Logging
  ;; --------------------------------------------------------------------------
  ;; Log state changes into a LOGBOOK drawer (not inline under heading)
  ;; Log DONE timestamp, log repeat state changes, log refile, log reschedule

  (setq org-log-done 'time)              ;; Log timestamp when task marked DONE
  (setq org-log-into-drawer "LOGBOOK")   ;; All state logs go into LOGBOOK drawer
  (setq org-log-repeat 'time)            ;; Log when repeating task resets state
  (setq org-log-refile 'time)            ;; Log timestamp when item is refiled
  (setq org-log-reschedule 'time)        ;; Log when scheduled date changes
  (setq org-log-redeadline 'time)        ;; Log when deadline changes
```

This ensures all state transitions produce timestamped entries in the LOGBOOK drawer, creating an audit trail for GTD processing.
</detail>
</task>

<task id="01-02-3">
<title>Configure GTD context tags with fast-tag selection</title>
<detail>
Add to the `(after! org)` block in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; GTD Context Tags
  ;; --------------------------------------------------------------------------
  ;; 6 context tags for GTD next-action filtering.
  ;; Tags are NOT mutually exclusive — a task can have multiple contexts.
  ;; Tags inherit from parent headings (org default behavior).
  ;; Fast-tag selection: press the shortcut key to toggle the tag.

  (setq org-tag-alist
        '((:startgroup)
          ("@home"     . ?h)
          ("@work"     . ?w)
          ("@errands"  . ?e)
          ("@phone"    . ?p)
          ("@computer" . ?c)
          ("@email"    . ?m)
          (:endgroup)))
```

Note on `:startgroup`/`:endgroup`: Despite using these group markers, they create a radio-button group (mutually exclusive) by default in org. Since the requirement says tags should NOT be mutually exclusive, we should use a flat list instead:

```elisp
  (setq org-tag-alist
        '(("@home"     . ?h)
          ("@work"     . ?w)
          ("@errands"  . ?e)
          ("@phone"    . ?p)
          ("@computer" . ?c)
          ("@email"    . ?m)))
```

Using a flat list (no `:startgroup`/`:endgroup`) means tags are independent toggles. User can press `C-c C-q` (or Doom's tag binding) to get the fast-tag interface where they press h/w/e/p/c/m to toggle each context.

IMPORTANT: Use the flat list (second version), NOT the startgroup version.
</detail>
</task>

<task id="01-02-4">
<title>Configure priority faces with color-coding</title>
<detail>
Add to the `(after! org)` block in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; Priorities
  ;; --------------------------------------------------------------------------
  ;; A/B/C priorities with visually distinct color-coded faces.
  ;; Colors chosen to match doom-tokyo-night palette.

  (setq org-priority-highest ?A)
  (setq org-priority-lowest  ?C)
  (setq org-priority-default ?B)

  (setq org-priority-faces
        '((?A . (:foreground "#ff6c6b" :weight bold))
          (?B . (:foreground "#ECBE7B" :weight bold))
          (?C . (:foreground "#98be65"))))
```

This gives immediate visual feedback: red=urgent, yellow=moderate, green=low. The `org-priority-default` of B means new tasks without explicit priority are treated as medium importance.
</detail>

<task id="01-02-5">
<title>Configure effort properties with t-shirt sizes</title>
<detail>
Add to the `(after! org)` block in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; Effort Estimation
  ;; --------------------------------------------------------------------------
  ;; T-shirt sizes for quick effort estimation.
  ;; Mapped to approximate time values for filtering/sorting.
  ;; Set effort with C-c C-x e (org-set-effort).

  (setq org-effort-durations
        '(("XS" . 15)      ;; 15 minutes
          ("S"  . 30)      ;; 30 minutes
          ("M"  . 60)      ;; 1 hour
          ("L"  . 120)     ;; 2 hours
          ("XL" . 240)))   ;; 4 hours

  ;; Column view format showing effort alongside TODO state and priority
  (setq org-columns-default-format
        "%40ITEM(Task) %TODO %3PRIORITY %10Effort(Effort){:} %TAGS")

  ;; Effort allowed values for quick selection
  (setq org-global-properties
        '(("Effort_ALL" . "XS S M L XL")))
```

`org-effort-durations` maps t-shirt labels to minute values, enabling org's effort-based filtering. `org-global-properties` defines the allowed values so `C-c C-x e` presents a selection list. `org-columns-default-format` provides a useful column view showing effort alongside other task metadata.
</detail>
</task>
