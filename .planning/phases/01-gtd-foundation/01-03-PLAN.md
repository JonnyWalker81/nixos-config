## Objective

Complete the GTD foundation by configuring refile targets scoped to GTD files with fuzzy completion (max 2 levels deep), archive strategy (per-source `_archive` files in `~/org/gtd/archive/`), an auto-archive function for items closed 30+ days ago, and manual archive keybinding. Then validate the entire Phase 1 by verifying all success criteria end-to-end.

## Context

- config-org-gtd.el now contains: org-directory, org-agenda-files, directory bootstrapping, TODO states, logging, context tags, priorities, effort (from Plans 01-01 and 01-02)
- Refile targets must include ALL GTD files: inbox.org, projects.org, someday.org, reference.org
- Max refile depth: 2 levels — means first-level and second-level headings are refile targets
- Refile completion should show hierarchy (e.g., "projects.org/Project A") for clarity
- Fuzzy completion is provided by Doom's vertico/orderless — `org-refile-use-outline-path` + `org-outline-path-complete-in-steps` enable it

### Discretion Decision: Archive Strategy

Using **per-source archiving** with archive files stored in the `archive/` subdirectory:
- `org-archive-location` set to `"~/org/gtd/archive/%s_archive::"` 
- This means `inbox.org` archives to `archive/inbox.org_archive`, `projects.org` archives to `archive/projects.org_archive`, etc.
- The `::` suffix means archived items go under a datetree or top-level in the archive file
- Per-source is simpler to trace (you know where an archived item came from) and avoids a monolithic archive file

### Discretion Decision: Auto-archive Implementation

A custom elisp function that:
1. Scans all GTD files for DONE/CANCELLED items
2. Checks the `CLOSED` timestamp property
3. If closed 30+ days ago, archives the item
4. Can be called manually via `M-x org-gtd-archive-stale` or bound to a key

This is cleaner than a hook (which could silently archive things) and gives the user explicit control. The 30-day window is configurable via a defvar.

```elisp
  ;; Refile
  ;; --------------------------------------------------------------------------
  ;; Refile targets: all GTD files, max 2 levels deep.
  ;; Shows file + heading path for clarity (e.g., "projects.org/Project A").
  ;; Uses vertico/orderless fuzzy completion (Doom provides this automatically).

        '(("~/org/gtd/inbox.org"     :maxlevel . 2)
          ("~/org/gtd/projects.org"  :maxlevel . 2)
          ("~/org/gtd/someday.org"   :maxlevel . 2)

  ;; Show full outline path in refile completion (file/heading/subheading)
  (setq org-refile-use-outline-path 'file)

  ;; Don't complete in steps — show full paths in a single completion interface
  ;; This works with vertico/orderless for fuzzy matching
  (setq org-outline-path-complete-in-steps nil)

  ;; Allow creating new parent nodes during refile (confirm first)
  (setq org-refile-allow-creating-parent-nodes 'confirm)

  ;; Cache refile targets for speed (clear cache with C-u C-u C-c C-w)
  (setq org-refile-use-cache t)
```

The `org-refile-use-outline-path 'file` setting makes refile show paths like "projects.org/Project Name" which gives clear context about where items will land. Combined with `org-outline-path-complete-in-steps nil`, the entire path is presented in a single vertico completion buffer with fuzzy matching.

<task id="01-03-3">
<title>Create auto-archive function for stale closed items</title>
<detail>
Add AFTER the `(after! org)` block (or at the end within it) in `users/doom.d/config-org-gtd.el`:

```elisp
  ;; --------------------------------------------------------------------------
  ;; Auto-archive stale items
  ;; --------------------------------------------------------------------------
  ;; Archive DONE/CANCELLED items that have been closed for 30+ days.
  ;; Call manually: M-x org-gtd-archive-stale
  ;; This is intentionally manual, not automatic, to avoid surprise archiving.

  (defvar org-gtd-archive-stale-days 30
    "Number of days after which DONE/CANCELLED items are considered stale for archiving.")

  (defun org-gtd-archive-stale ()
    "Archive all DONE/CANCELLED items closed more than `org-gtd-archive-stale-days' days ago.
Operates on all GTD agenda files."
    (interactive)
    (let ((cutoff (time-subtract (current-time)
                                 (days-to-time org-gtd-archive-stale-days)))
          (archived-count 0))
      (dolist (file (org-agenda-files))
        (with-current-buffer (or (find-buffer-visiting file)
                                 (find-file-noselect file))
          (org-map-entries
           (lambda ()
             (let ((closed-str (org-entry-get nil "CLOSED")))
               (when (and closed-str
                          (time-less-p (org-time-string-to-time closed-str) cutoff))
                 (org-archive-subtree)
                 (setq archived-count (1+ archived-count)))))
           "/DONE|CANCELLED" 'file)))
      (message "Archived %d stale items (closed > %d days ago)"
               archived-count org-gtd-archive-stale-days)))
```

Place this function inside the `(after! org)` block since it uses org functions. The `/DONE|CANCELLED` matcher in `org-map-entries` matches items in those TODO states. The function iterates all agenda files, checks the CLOSED property timestamp, and archives items past the cutoff date.
</detail>
</task>
